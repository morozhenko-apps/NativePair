## First OBEX session attempt

Both MAP and PBAP `CreateSession` calls returned a session object and that object could be introspected. The first version of the probe did not observe the expected target-specific interface on either session object:

- MAP: `session_created=yes`, `session_introspection=yes`, `target_interface_present=no`;
- PBAP: `session_created=yes`, `session_introspection=yes`, `target_interface_present=no`.

This result is **inconclusive**, not a failed capability. BlueZ 5.85 source registers `MessageAccess1` and `PhonebookAccess1` on the session object as part of the target driver probe, so the next diagnostic records the session target UUID and all exported interface names before deciding whether level 3 is proven.

The phone displayed an authorization prompt during the MAP attempt. PBAP did not produce equivalent visible feedback after acceptance.

## BlueZ mpris-proxy crash

During the MAP attempt, the Ubuntu `mpris-proxy` user process terminated with SIGSEGV.

Observed package:

- `bluez/5.85-4ubuntu0.2`.

This is tracked separately from NativePair's MAP/PBAP result. The crash pattern is consistent with a known upstream `mpris-proxy` null-dereference around OBEX property handling. Controlled reruns should stop the user `mpris-proxy.service` temporarily so media-proxy failure cannot contaminate protocol observations.
